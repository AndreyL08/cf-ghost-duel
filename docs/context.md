# CF Ghost Duel: контекст проекта

## Задача

Есть сайт cf-1v1.vercel.app (автор — UnemployedProgrammer на Codeforces, исходники закрыты). На нём проводятся дуэли 1v1 на задачах Codeforces:

- выбираешь фильтры и ищешь соперника;
- сайт выдаёт случайную задачу через API Codeforces;
- кто первым получит AC со своего аккаунта CF, тот и победил.

Проблема: на сайте почти нет онлайна, а для дуэли нужен второй живой человек. Цель — заменить его ИИ или ботом, который имитирует соперника.

## Какие варианты рассматривались

1. **Бот как живой игрок на чужом сайте.** Отвергнут:
   - нужен второй аккаунт на CF и на сайте;
   - бот должен реально сдавать AC, а API для отправки решений у CF нет, остаётся автоматизация через браузер с Cloudflare и капчами;
   - нужно реверсить внутреннее API сайта, которое сломается при любом обновлении;
   - бот накручивал бы чужой лидерборд.
2. **Своя страница с виртуальным соперником.** Выбран этот вариант. Соперник ничего не отправляет на CF: это симуляция, которая в нужный момент объявляет «решил». От CF нужны только выбор задачи и проверка AC пользователя.
3. **LLM-агент, который реально решает задачу.** Отвергнут как основной соперник: сила LLM не похожа на человеческую, лёгкие задачи он решает мгновенно, сложные непредсказуемо. Может пригодиться позже для чата или разбора после дуэли.

## Реализация (MVP)

Файл: `cf-ghost-duel.html` — один самодостаточный HTML без сборки, интерфейс на русском. Его можно открыть локально или задеплоить на Vercel или GitHub Pages как `index.html`.

### Доступ к API Codeforces

- Запросы идут через обычный `fetch` (`credentials: "omit"`, `cache: "no-store"`): API CF отдаёт `Access-Control-Allow-Origin: *`, в том числе на ответы с ошибкой, поэтому текст ошибки (`comment`) виден.
- Раньше использовался JSONP, но от него отказались: при HTTP 400 браузер не выполняет скрипт, и причина ошибки терялась. Кроме того, `contest.standings` с параметром `jsonp` отклоняется (см. ниже).
- **`contest.standings` для обычных (не gym) контестов доступен только как анонимный GET вида `?contestId=<id>` без других параметров.** Запрос с `handles`, `showUnofficial`, `jsonp` и т.п. возвращает 400. Поэтому таблица грузится целиком: для большого раунда это около 14 МБ JSON, примерно 630 КБ в gzip.
- Все вызовы выстроены в очередь с интервалом не меньше 2.1 с, потому что лимит CF — один запрос в 2 секунды.
- При сетевой ошибке или «Call limit exceeded» запрос повторяется до двух раз.
- В песочнице артефактов claude.ai страница работать не будет: CSP блокирует codeforces.com. Поэтому проект распространяется файлом, а не артефактом.

### Флоу

1. **Настройки:** хэндл, диапазон рейтинга задач, уровень соперника R, лимит времени (15–120 минут), теги (чипы, режим «все сразу» или «любой из»), галочка адаптивного уровня. Всё сохраняется в localStorage.
2. **Поиск соперника:**
   - `problemset.problems` — берутся задачи с рейтингом, без gym (`contestId < 100000`) и без тега `*special`;
   - `user.status?handle=` — даёт множество решённых задач (verdict OK) и максимальный `id` посылки (`lastId`);
   - из кандидатов по фильтрам выбирается случайная задача;
   - для неё строится соперник (см. ниже).
3. **Экран «Соперник найден»:** показан рейтинг соперника, рейтинг задачи и лимит. Условие скрыто до нажатия «Старт».
4. **Дуэль:**
   - таймер привязан к `Date.now()`, поэтому не сбивается в фоновой вкладке;
   - `user.status?from=1&count=25` опрашивается каждые 6 с (каждые 3 с в режиме ожидания);
   - учитываются только посылки с `id > lastId` на эту же задачу (`contestId` + `index`);
   - у соперника показываются неудачные попытки и AC по таймлайну;
   - теги задачи скрыты до конца дуэли.
5. **Итог:** победа, поражение или ничья, раскрытие личности призрака, запись в историю (последние 50 дуэлей, счёт W/L/D в шапке). В адаптивном режиме уровень бота меняется на +50 за победу и −50 за поражение.
6. Активная дуэль хранится в localStorage и переживает перезагрузку страницы.

### Соперник-призрак (`buildGhost`)

1. `contest.ratingChanges?contestId=` — участники контеста с `oldRating`. Пустой ответ или ошибка «Rating changes are unavailable» означают нерейтинговый контест, тогда используется синтетический соперник. Если участников уровня R ± 600 меньше 3, таблица не загружается вовсе.
2. `contest.standings?contestId=` — полная таблица (без параметров, см. выше). Строки фильтруются по `participantType === "CONTESTANT"` и наличию хэндла в `ratingChanges`.
3. Пул — строки с `|oldRating − R| ≤ d`, где d последовательно 100, 200, 350, 600, пока в пуле не наберётся хотя бы 15 человек. Если меньше 3, используется синтетический соперник.
4. Индекс задачи находится в `st.problems`, из пула случайно выбирается одна строка.
5. Если у выбранного участника задача решена (`points > 0` и задан `bestSubmissionTimeSeconds`):
   - `solveSec = max(60, ac − prevAc)`, где `prevAc` — самый поздний его AC по другим задачам до этой.
   - Это поправка на то, что в контесте он сначала решал другие задачи.
6. Если задача не решена, призрак её не решит. Это даёт реалистичную вероятность победы.
7. Неудачные попытки: их число берётся из `rejectedAttemptCount` (не больше 8), времена случайные в интервале [0.3; 0.95] от времени решения (или от лимита, если задача не решена).
8. Для финального экрана сохраняются хэндл, рейтинг, название контеста, место, реальное время AC, а также сколько участников из пула решили задачу.
9. Если призрак не нашёлся (нерейтинговый контест, мало участников уровня R, ошибка API), поиск пробует ещё до двух случайных задач и только потом соглашается на синтетического соперника. Причина показывается на экране «Соперник найден», ошибки API пишутся в консоль.

### Синтетический соперник (fallback)

- Вероятность решить: `P = 1 / (1 + 10^((rating − R)/400))`.
- Время: медиана `900 · 2^((rating − R)/300)` секунд, логнормальный шум с σ = 0.45, минимум 90 с.
- 0–4 неудачные попытки.

### Определение победителя (`resolveDuel`)

Обозначения:
- `gAc` — время AC призрака, если оно не больше лимита, иначе null;
- `ac` — первая посылка пользователя с вердиктом OK и временем `t ≤ limit`.

Правила:
1. Если `ac` есть и (`gAc == null` или `ac.t ≤ gAc`), это **победа**.
2. Иначе `cutoff = gAc ?? limit`. Пока прошло меньше `cutoff`, дуэль идёт.
3. После `cutoff` результат объявляется только когда:
   - нет посылок пользователя в статусе TESTING, отправленных до `cutoff`;
   - и был опрос, начатый позже `start + cutoff + 1.5 с`.
   До этого страница в режиме ожидания и опрашивает каждые 3 с.
4. Затем, если `gAc` есть, это **поражение**, иначе **ничья**.
5. Отдельно есть кнопки «Сдаться» (засчитывается поражение) и «Другая задача» на экране готовности (дуэль не засчитывается).

Время посылки пользователя считается как `creationTimeSeconds − start/1000`, где `start` берётся по локальным часам. Расхождение часов с сервером CF обычно несущественно.

Логика `resolveDuel` проверена в node на сценариях:
- пользователь раньше;
- призрак раньше при свежем и устаревшем опросе;
- посылка в тестировании до AC призрака;
- AC пользователя после призрака;
- никто не решил;
- AC пользователя после лимита.

### Дизайн

- Шрифты: Unbounded (заголовки), Onest (текст), JetBrains Mono (таймер и данные); все с кириллицей.
- Светлая и тёмная темы через CSS-токены.
- Цвета рейтинга как на CF: серый, зелёный, бирюзовый, синий, фиолетовый, оранжевый, красный.
- Две колонки «Ты» и «Соперник»; на телефоне они складываются в одну.

## Статус и ограничения

- Проверено на живом API в headless Chromium: поиск находит реального призрака за 3–8 с, опрос посылок работает.
- `contest.ratingChanges` и `contest.standings` для больших раундов весят несколько МБ (в gzip сотни КБ), кэша между сессиями нет.
- Если задача взята из Div. 1 раунда, участников уровня ~1500 там нет, и пул расширяется до ±600: соперник может оказаться заметно сильнее R.
- В Div1/Div2 параллельных раундах учитывается только тот `contestId`, под которым задача лежит в problemset.
- Если пользователь сдаст ту же задачу под другим `contestId` (div1-версия), страница этого не увидит.

## Идеи на потом

- Кэшировать `problemset.problems` в IndexedDB.
- Показывать рейтинг пользователя через `user.info` и по умолчанию ставить уровень бота равным ему.
- Разрешить выбор только недавних контестов или исключать задачи, которые пользователь уже пробовал.
- LLM-соперник для чата и разбора задачи после дуэли.
- Режим нескольких задач подряд, как team battle на оригинальном сайте.
